# Asset Planner · 资产统计与定投工具

一个用来记录和统计个人资产配置、复盘历史持仓、对照每日定投金额的小工具。数据默认保存在浏览器本地，可选配置 Supabase 实现多设备自动云同步，全程免登录。

## 这个工具解决什么问题

- **资产统计**：把散落在不同账户里的债券、黄金、基金、股票归到一处，按品类看清底仓分布和占比。
- **复盘对照**：随时保存当前持仓快照，回看任意两天的变化，搞清楚这段时间是加仓了、减仓了、还是涨跌带来的差异。
- **定投统计**：把每天定投的金额汇总成日定投额、月定投额，对照月薪看自己有没有超支，直观明了。
- **再平衡**：设定各品类目标占比，实时查看偏离度，并获得基于真实持仓的调仓建议。

## 功能说明

### 总览
一屏看清四个数字：底仓总额、日定投额、月定投额、月薪占比。下面是底仓和定投两张占比饼图。

饼图右侧的品类图例可以点——点一下，这个品类就不参与统计了，剩下的品类重新算占比；再点一下就恢复。明细里每一项也能单独点左侧小圆点切换，不想看某一项就点掉，想看回来再点一下，不会消失找不到。

配置了目标占比后，总览页还会显示两块再平衡内容：

- **目标配置偏离**：每个品类的实际占比与目标占比的对比条，偏离超过 ±5 个百分点会标红，一目了然谁超配、谁低配。
- **调仓建议**：按「目标金额 = 底仓总额 × 目标占比」算出每个品类应加仓或减仓的具体金额。

### 底仓
管理手上的持仓。可以按品类分 Tab 看，也能按名字搜索。支持多套方案，比如「主仓位」「实验仓位」分开记。

「保存今日记录」会把当前持仓存成一张快照。下次打开可以看到和上次的差额，是加仓了还是市值变了，一目了然。

### 快照对比（半年复盘）
在「历史记录」里勾选任意两条快照即可对比：

- 切换**底仓 / 定投**范围，金额 / 比例两种口径，按品类或按明细两个粒度。
- 变化最大的行会高亮，小屏也能快速抓住重点。
- 对比结果下方会结合最新快照的目标配置给出**调仓建议**，告诉你这个半年度该往哪个方向调。

### 定投
记录每天定投多少钱。自动算出月定投额（按 22 个交易日），对照你设的月薪和比例上限，超了会标红提醒。

饼图和明细的交互跟底仓一样：图例点掉就排除，明细小圆点切换显隐，随时恢复。

### 自选
把关注的基金、股票先存起来，下次在底仓或定投页添加时直接选，不用反复输入代码和名字。

支持 Excel（.xlsx）批量导入：「导入」→ 选择文件。表头列为 `代码 | 名称 | 品类 | 备注`（名称必填），品类列填品类名，留空或不识别会自动归入第一个品类；重复条目自动跳过。提示：代码在 Excel 里建议设成**文本**格式，避免前导零被吞。

### 设置
- **工资约束**：月薪、定投比例上限。
- **目标配置（再平衡）**：为每个品类输入目标占比，实时显示合计并校验是否等于 100%；留空的品类不参与提醒。
- **品类管理**：自定义品类和颜色。内置品类不能删，自己加的可以。
- **数据管理**：导出 JSON 备份、导入恢复（导入前会校验文件并显示备份概况与覆盖确认）、清空所有数据。

## 半年复盘工作流

1. 平时随手点「保存今日记录」，快照会自动累积。
2. 半年后在「设置 → 目标配置」确认各品类的目标占比（合计 100%）。
3. 打开「历史记录」，勾选半年首尾两条快照 → 对比：看底仓和定投各品类变化、总金额增减。
4. 结合对比弹窗和总览页的调仓建议，决定加仓/减仓方向。
5. 想换设备或清理数据？「导出 JSON」带走，「导入 JSON」时工具会先校验文件、显示备份概况，确认后才会覆盖。

## 关于数据安全

未配置云同步时，所有数据只保存在你浏览器的 localStorage 里，不会上传到任何服务器。关闭浏览器、断网都能正常用。想换设备就导出一份 JSON 带走。

配置 Supabase 云同步后，数据会整份同步到你的 Supabase 项目（一张 `user_data` 表），PC / 手机之间自动同步。**身份靠你在设置页输入的密码（PIN）区分**：密码经 SHA-256 派生为云端 user_id，不同密码对应不同的云端数据，互相隔离。**这是"钥匙隔离"而非强鉴权**——云端数据本身不设鉴权，知道密码就等于能访问对应数据，所以请用足够强的密码、别告诉别人，也别把链接发给别人。

## 启用云同步（约 5 分钟，一次性）

1. 注册并登录 [supabase.com](https://supabase.com)，创建一个免费项目
2. 项目 → **SQL Editor**，粘贴 [db/schema.sql](db/schema.sql) 的全部内容并运行
3. 项目 → **Settings → API**，复制 Project URL 与 anon key
4. 本地开发：在根目录创建 `.env`（参照 [.env.example](.env.example)），填入两个变量：
   - `VITE_SUPABASE_URL`（Project URL）
   - `VITE_SUPABASE_ANON_KEY`（anon key）
5. GitHub 仓库 → **Settings → Secrets and variables → Actions**，新增同名 secret：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`
6. 推到 main 自动部署
7. 打开页面 → **设置 → 身份校验**，输入一个只有你知道的密码并「启用同步」。同一密码的设备共享同一份数据，不同密码互相隔离

启用后无需登录：任何修改自动上传，打开或切回页面时自动拉取，两台设备同时打开会实时同步。`.env` 不会被提交，密钥只放 GitHub Secrets。

> 注意：密码只存在本机浏览器里，**忘记密码后新设备将无法访问云端数据**（当前设备仍可继续使用）。切换身份时，本机数据会同步到新密码对应的云端行，旧密码的云端数据保留但不再同步。

## 本地运行

需要 Node.js 20 以上，推荐用 [Bun](https://bun.sh/)。

```bash
bun install      # 装依赖
bun run dev      # 开发
bun run build    # 打包，产物在 dist/
```

用 npm 也行：

```bash
npm install
npm run dev
npm run build
```

## 部署到 GitHub Pages

推送到 main 分支会自动部署。部署前在仓库 **Settings → Pages → Build and deployment → Source** 选 `GitHub Actions`。部署后访问 `https://<你的用户名>.github.io/asset-planner/`。

## 技术栈

React 18 + TypeScript + Vite + Zustand + Recharts + Tailwind CSS + Supabase（可选云同步）。
